## Stages, in order

<!-- crew:discoverable capability=mcp:tracker -->

> **▸ Fill:** the ordered stage names an item moves through, from first capture to done or retired — one line each, with a sentence on what the stage is for. Where the tracker has a workflow or status field for planning items, its states are the starting point; note any state that is not a real stage (e.g. "Parked").

## Gate criteria per stage

> **▸ Fill:** for each stage, the criteria an item must meet to **enter** it. Mark every criterion `must` (holds the item back) or `should` (reported, never holds it back). Each gate builds on the ones before it — an item entering stage 3 must also meet the musts of stages 1 and 2 — so list only what each stage adds.

## Discovery-stage items

> **▸ Fill:** the lighter criteria for items still in discovery (a problem being explored, not a solution being built) — typically a hypothesis, the question being answered, a timebox, and what evidence ends discovery. Say which full-gate criteria do **not** apply to them.

## Item types that skip criteria

> **▸ Fill:** the item types your org lets skip particular criteria, and exactly which criteria each skips and why. readiness-gates skips nothing that is not listed here; leave this empty if every item meets every gate.

## Review milestones

> **▸ Fill:** recurring reviews where readiness is checked (cycle planning, portfolio review, launch review), which stage an item should have reached by each, and the role that runs it. Roles, never people.
